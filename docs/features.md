# 기능 소개

> 이 프로그램이 **무엇을 할 수 있는지**를 기능별로 설명한다.
> 어떻게 쓰는지는 [사용자 안내서](user-guide.md), 왜 그렇게 되어 있는지는
> [DECISIONS.md](DECISIONS.md)를 본다.
> 최종 확인: 2026-09-04 (v1.3.0)

작업은 크게 **두 갈래**다. 하나만 쓰는 사람이 대부분이다.

| | 무엇을 하나 | 어디부터 읽나 |
|---|---|---|
| **추출** | 근현대 논문·단행본 스캔본에서 텍스트만 빠르게 뽑아 검색되는 PDF로 | 아래 1번 |
| **교감** | 고전 원전을 읽고 편성·표점·현토·번역·주석을 붙여 연구 | 아래 2~11번 |

### 1. 추출 모드 — 근현대 스캔본에서 텍스트만 빠르게

![추출 모드 — 텍스트 추출 패널](screenshots/12_extract.jpg)

옛날 논문·단행본처럼 표점·현토·이체자가 필요 없는 자료를 위한 **작업 모드**입니다.
인덱스 줄 오른쪽 끝의 「추출 모드로 →」 버튼으로 «교감 모드»와 «추출 모드»를 오가면
교감 전용 인덱스 7개(편성·표점·현토·번역·주석·인용·이체자)가 숨습니다
(표시만 바뀌고 데이터는 그대로이며, 프로필은 문헌마다 기억됩니다).

- **자동 진단**: 등록하는 순간 텍스트 레이어 유무를 가려 줍니다. 이미 텍스트가 있으면 **OCR을 아예 건너뜁니다.**
- **권 단위 일괄 OCR**: 페이지마다 레이아웃을 잡을 필요가 없고, 중단해도 **이어서** 돕니다.
- **쪽별 검수**: 쪽마다 줄 수·글자 수·본문 앞머리를 한눈에 보고 확인 표시를 남깁니다.
  진행률(3/15쪽 확인)이 표시되고, **다 확인하지 않은 채 내보내려 하면 알려 줍니다.**
  문제가 보이면 그 자리에서 **교정 인덱스(대조)·레이아웃 인덱스(영역)**으로 넘어갑니다 —
  몇 글자 오독은 다시 OCR 해도 대체로 같으므로 손으로 고치는 편이 빠릅니다.
- **부분 재-OCR**: 결과가 나쁜 몇 쪽만 레이아웃을 나눈 뒤 그대로 다시 실행하면
  **고친 쪽만** 돕니다. 쪽 번호를 기억해 입력할 필요가 없습니다.
- **텍스트 레이어 PDF(검색되는 PDF)**: 원본 이미지 위에 보이지 않는 텍스트를 얹어 내보냅니다.
  사이드카 `.txt`와 달리 **복사·Ctrl+F·구조 분석·참고문헌 추출**이 한꺼번에 살아납니다.
  폰트를 임베드하므로 한시 인용문의 벽자(`儂`·`纔`·`鬬` 등)도 그대로 검색됩니다.
  결과는 문헌 폴더의 `exports/`에 새 파일로 나가고, 「만든 PDF 내려받기」로 받으면
  **원본 논문 파일명 그대로**(`저자_연도_제목.pdf`) 저장됩니다.

> 한글이 포함된 문헌은 **LLM Vision** 엔진을 쓰세요. NDL 계열 엔진은 한글을 인식하지 못합니다.

**형광 표시는 기본 설치만으로 제자리에 뜹니다.** 읽기는 LLM Vision이,
글자 위치 찾기는 PaddleOCR 검출이 맡는 분업입니다
(실측: 15쪽 논문에서 502줄 중 433줄이 제자리). PaddleOCR는 기본 번들입니다.

**논문이 수십 편이면 폴더째** 처리할 수 있습니다. 스캔본만 골라 OCR하고,
원본은 아카이브로 옮긴 뒤 텍스트 레이어 PDF를 원래 이름 그대로 제자리에 놓습니다.

```bash
# 한 편만 — 서고를 미리 만들 필요가 없습니다
ctb ocr "논문.pdf" --execute

# 폴더째 — 기본이 미리보기라 --execute 없이는 아무것도 바뀌지 않습니다
uv run python -m cli embed-folder "C:/논문" --library C:/작업서고
uv run python -m cli embed-folder "C:/논문" --library C:/작업서고 --limit 1 --execute
```

기본이 미리보기라 `--execute` 없이는 아무것도 바뀌지 않고, 중단해도 다음 실행이 이어서 합니다.
실행 전에 **어느 LLM 모델이 도는지** 한 줄 찍고(`--model`로 고정 — `ctb models`의 번호나 이름 일부),
자주 쓰는 옵션은 `ctb config`로 저장해 둡니다.

자세한 사용법: [사용자 안내서 7-A](user-guide.md#7-a-근현대-논문에서-텍스트만-빠르게-뽑기)

### 2. 레이아웃 분석 + OCR — 원본 이미지에서 텍스트 추출

![레이아웃 분석 화면](screenshots/02_layout.jpg)

PDF/이미지 위에 **읽기 순서대로 번호가 매겨진 파란색 블록**이 표시됩니다.
고전적에 최적화된 NDL古典籍OCR(Full/Lite), 근현대 문서용 NDLOCR, LLM 비전, PaddleOCR 중 원하는 엔진을 선택해서 OCR을 실행할 수 있습니다.

- **자동감지**: 버튼 하나로 페이지 전체의 텍스트 영역을 자동으로 잡아줍니다
- **수동 조정**: 블록을 드래그해서 위치·크기·읽기 순서를 직접 수정할 수 있습니다
- **모든 블록 OCR / 선택 블록 OCR**: 전체 또는 원하는 영역만 골라서 인식합니다

### 3. 교정 — OCR 결과를 원본과 나란히 비교하며 수정

![교정 화면](screenshots/03_correction.jpg)

왼쪽 원본 이미지를 보면서 오른쪽에서 OCR 인식 결과를 직접 수정합니다.
**글자 교정**(유형 지정 가능)과 **자유 편집**(글자 추가/삭제/수정) 두 가지 모드를 토글로 전환할 수 있습니다.
**일괄 교정**(이체자 사전 기반)과 **대조 뷰**(OCR 원본 vs 교정본 비교)도 지원합니다.

### 4. 편성 — 글이 어디서 바뀌는지 정하기 (v1.3)

![편성 화면 — 지금 경계와 내용 트리](screenshots/08_composition.jpg)

교정이 끝난 확정본에서 **글의 경계**를 정합니다. 경계 하나가 「여기서 새 글이 시작한다」이고,
끝은 다음 경계가 정합니다. 그렇게 만들어진 단위(권·기사·조각)가 표점·현토·번역·주석의
작업 단위가 됩니다.

- **이 책의 규약(답 한 줄)** — 사람이 책을 보는 순서(목차 → 되풀이되는 기호·내려쓰기 → 행 첫머리·행 끝·기호 뒤에
  되풀이되는 글 → LLM → 사람)로 확정본 전체를 세어 «이 책의 규약: 기호 「○」 217회»처럼 한 줄로 답합니다. 판심·엽수처럼
  쪽마다 같은 자리에 오는 것, 줄지어 오는 덩어리는 뺍니다. 답이 틀리면 「자세히 · 고치기」에서 신호를 켜고 끕니다.
  고른 것이 이 문헌의 규칙(설정)이 되고, 코드에 책 이름은 없습니다. 모델을 부르는 단추는 「LLM에 묻기」 하나 —
  창에서 목차 항목 구조화·표제 어휘 뽑기·시작 표지 묻기를 골라 텍스트 조각만 보내고, 전문에서 되풀이되는 것만
  받아들입니다.
- **경계 제안** — 그 규칙으로 권 전체 확정본에서 후보를 찍어 줍니다. 체크한 것만 단위가 됩니다.
- **자동 트리** — 규칙이 없으면 먼저 찾아 저장하고, 목차·卷頭·날짜·권점·어휘로 묶음 > 기사 > 조각의 개요를
  한 번에 세웁니다. 언제나 규칙만 — LLM은 편성 인덱스 「LLM에 묻기」에서 목차 구조화를 켠 뒤의 「전부 적용해 새로 세우기」에서만.
- **찍기** — 원본 이미지나 교정 텍스트에서 자리를 눈으로 찍어 경계를 놓습니다.
- **본문을 저장하지 않습니다.** 단위의 본문은 읽을 때마다 확정본에서 잘라 오므로,
  나중에 교감해도 그대로 따라옵니다.
- 편성은 **원본 저장소**의 일입니다. 문헌만 고르면 되고, 한 문헌에 해석 저장소가 여럿이면
  같은 편성을 함께 씁니다. 해석 저장소는 표점 인덱스부터 씁니다.

### 5. 표점(句讀) — 고전 한문에 구두점 찍기

![표점 화면](screenshots/04_punctuation.jpg)

교정이 끝난 텍스트에 **문장 부호(구두점)를 삽입**합니다.
미리 설정된 부호 세트를 사용하거나, AI에게 표점 초안을 요청할 수도 있습니다.

### 6. 현토(懸吐) — 한문에 한국어 토씨 달기

![현토 화면](screenshots/05_hyeonto.jpg)

표점이 완료된 문장에 **한국어 토(吐)를 삽입**하는 단계입니다.
한문 원문 옆에 작은 글씨로 토가 표시되며, AI 보조 기능도 사용할 수 있습니다.

### 7. 번역 — LLM 보조 또는 수동 번역

![번역 화면](screenshots/06_translation.jpg)

원문을 현대 한국어로 번역합니다. **Ollama(로컬), OpenAI OAuth, Gemini, OpenAI, Anthropic** 등 다양한 LLM에 번역 초안을 요청하고, 연구자가 직접 수정·확정합니다. LLM이 응답하지 않으면 자동으로 다음 프로바이더로 폴백합니다.

### 8. 주석 — 태그, 사전형 주석, 인용 마크

![주석 화면](screenshots/07_annotation.jpg)

번역이 끝난 텍스트에 **연구 주석을 추가**합니다.
인명·지명·서명 등의 **태그**, 단어의 뜻풀이를 기록하는 **사전형 주석**, 다른 문헌의 해당 구절을 연결하는 **인용 마크** 세 가지 유형을 지원합니다.

### 9. 이체자 사전 — 異體字 자동 교정

![이체자 사전 화면](screenshots/09_variant.png)

고전 한문에 자주 등장하는 **이체자(異體字) 대응표**를 관리합니다.
예를 들어 「萬→万」, 「國→国」 같은 자형 변환을 등록해두면 OCR 결과를 일괄 교정할 때 자동으로 적용됩니다.

### 10. Git 버전 관리 — 모든 작업 이력을 안전하게 보존

![Git 이력 화면](screenshots/10_git_history.jpg)

원본 저장소와 해석 저장소가 **각각 독립된 Git 저장소**로 관리됩니다.
커밋 로그와 사다리형 그래프로 작업 이력을 한눈에 볼 수 있고, 언제든 이전 상태로 되돌릴 수 있습니다.

### 11. 서고 관리 — 문헌과 해석을 체계적으로 정리

![설정 화면](screenshots/11_settings.png)

여러 문헌과 해석 저장소를 하나의 **서고(Library)**로 묶어 관리합니다.
백업 경로 설정, 원격 저장소(GitHub 등) 연결, JSON 스냅샷 내보내기/가져오기를 GUI에서 바로 할 수 있습니다.

## 기능 요약

| 영역 | 기능 |
|------|------|
| **원본 관리** | PDF/이미지 뷰어, **나중에 권 추가**, 레이아웃 분석, OCR(NDL古典籍OCR Full/Lite + NDLOCR + LLM 비전 + PaddleOCR) |
| **편성** | 글 단위의 경계 정하기 — 이 책의 규약(층계)·경계 제안·자동 트리·찍기. 본문은 저장하지 않고 확정본에서 잘라 오므로 교감이 자동 반영 |
| **해석 작업** | 표점(句讀), 현토(懸吐), 번역(LLM+수동), 주석(태깅+사전형) |
| **연구 도구** | 인용 마크, 사전 내보내기/가져오기, 이체자 사전, 인용 양식 관리 |
| **저장소 관리** | 원본·해석 분리 Git 저장소, 사다리형 그래프, JSON 스냅샷 |
| **텍스트 가져오기** | **PDF 텍스트 레이어 → L4**(추출 모드 「텍스트 바로 가져오기」, 동작함) · 외부 HWP·PDF 파일을 새 문헌으로 + LLM 원문/번역 분리(화면 잠김, D-037) |
| **LLM 연동** | Ollama, OpenAI OAuth, Gemini, OpenAI, Anthropic (5단 자동 폴백) + 설정 화면의 연결·인증 상태 표시. 모델 목록은 API에서 받아 낡지 않음 |
| **처음 설정·업데이트** | Windows 설치 파일 `CTB-Setup.exe`(폴더·엔진 고르면 끝, D-113), 처음 설정 마법사(서고 → 글자 인식 엔진 → AI 연결), API 키·엔진 설치·ChatGPT 로그인·Ollama 로그인과 비전 모델 골라 받기(기본은 클라우드, D-114)를 전부 화면의 단추로(D-102·D-106·D-107), 앱 안에서 새 판 받기(D-103), 켤 때 저절로 받기·zip 설치도 갱신(D-112) |
| **추출 모드** | 작업 모드(교감/추출) 전환, 텍스트 레이어 진단, 권 단위 일괄 OCR(중단·재개·부분 재실행), 쪽별 검수(확인 진행률·교정/레이아웃 연결), **텍스트 레이어 PDF(검색되는 PDF) 내보내기** |
